【缺陷标题】新增用户时密码传空仍创建成功，能造出密码为空的账号

【所属模块】系统管理 / 用户管理
【接口】POST /system/user
【严重程度】中

【复现步骤】
1. 登录获取 token

   POST http://localhost:8080/login
   Body: {"username":"admin","password":"admin123","code":"","uuid":""}

2. 新增用户，password 传空字符串：

```bash
curl --location --request POST 'http://localhost:8080/system/user' \
     --header 'Authorization: Bearer <登录后获取的token>' \
     --header 'Content-Type: application/json' \
     --data-raw '{"userName":"probe1000275627","nickName":"空密码","password":""}'
```

3. 回查这个用户：

```bash
curl --location --request GET 'http://localhost:8080/system/user/list?pageNum=1&pageSize=100&userName=probe1000275627' \
     --header 'Authorization: Bearer <token>'
```

【预期结果】
password 应做非空校验，传空应返回「密码不能为空」。

依据：同一个接口的其他必填字段都有非空校验，实测对照如下——

| 传空字段 | 实际返回 |
| --- | --- |
| userName | 500 用户账号不能为空 |
| nickName | 500（有校验） |
| **password** | **200 操作成功（没有校验）** |

同样是必填字段，userName / nickName 都拦住了，password 没有，说明是漏了。

【实际结果】
HTTP 200，业务 code=200「操作成功」，并且用户**真的创建成功了**：

```
回查结果：userId=172，userName=probe1000275627，phonenumber 为空
```

自动化用例对应：
testcase/test_user.py::TestUserCrud::test_add_user_data_driven[密码为空【缺陷：未校验密码非空】]
当前显示为 XFAIL（已备案的已知缺陷）。

用 `pytest --runxfail` 强制跑出来的失败信息：
```
AssertionError: 【密码为空【缺陷：未校验密码非空】】期望 code=500，实际 200 - 操作成功
```

【影响】
1. 密码是登录凭据，非空校验缺失属于基础校验缺失
2. 能创建出密码为空的账号，这类账号是脏数据
3. 如果其他地方复用了同一套校验（比如批量导入用户），问题会一起扩散

【建议】
给 SysUser.password 补上 @NotBlank 校验，和 userName 保持一致。
