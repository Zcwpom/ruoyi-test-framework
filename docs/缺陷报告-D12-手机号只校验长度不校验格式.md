【缺陷标题】手机号只校验长度不校验格式，传 8 位数字也能创建成功

【所属模块】系统管理 / 用户管理
【接口】POST /system/user
【严重程度】低

【复现步骤】
1. 登录获取 token

2. 新增用户，phonenumber 传一个 8 位数字（明显不是手机号）：

```bash
curl --location --request POST 'http://localhost:8080/system/user' \
     --header 'Authorization: Bearer <token>' \
     --header 'Content-Type: application/json' \
     --data-raw '{"userName":"probe1200275627","nickName":"非法手机号","password":"Test@123456","phonenumber":"89427641"}'
```

3. 回查这个用户：

```bash
curl --location --request GET 'http://localhost:8080/system/user/list?pageNum=1&pageSize=100&userName=probe1200275627' \
     --header 'Authorization: Bearer <token>'
```

【预期结果】
phonenumber 应做格式校验（国内手机号 11 位、以 1 开头），
传 89427641 这种值应返回「手机号码格式不正确」。

依据：这个字段是有校验的，只是漏了格式这一项 ——
传 12 位手机号时会返回「手机号码长度不能超过11个字符」，
说明长度校验在，格式校验不在。

【实际结果】
HTTP 200，业务 code=200「操作成功」，用户创建成功：

```
回查结果：userId=174，userName=probe1200275627，phonenumber=89427641
```

自动化用例对应：
testcase/test_user.py::TestUserCrud::test_add_user_data_driven[手机号格式非法【缺陷：只校验长度不校验格式】]
当前显示为 XFAIL（已备案的已知缺陷）。

对照实测：

| phonenumber 取值 | 业务 code | 返回 |
| --- | --- | --- |
| 89427641（8 位） | 200 | 操作成功，创建成功 |
| 138000012345（12 位） | 500 | 手机号码长度不能超过11个字符 |

【影响】
1. 可以存入明显不是手机号的值，属于脏数据
2. 依赖手机号的后续功能（短信通知、找回密码等）会踩到这个数据
3. 属基础格式校验缺失

【建议】
给 SysUser.phonenumber 补一个格式正则，比如：

```java
@Pattern(regexp = "^$|^1[3-9]\\d{9}$", message = "手机号码格式不正确")
```
